'C' Language Example Program
=================================
File: C:\WDC_SDS\examples\csamp\Readme.doc
1/29/2004
Note: see Startups for the 134 & 265

The WDC_SDS\examples\csamp directory contains the 'C' version of the EXMPL1 program. 
See the README.TXT file in the parent directory for more information on the function of the program.

This program is written in 'C' and will run on either the 65C02 or the 65C816 cores. 
The same C program will work regardless which compiler is used. 
There are two different startup assembly language programs however.

The first, WDC_Cstartup_02.ASM, is used with the 65C02 compiled program. 
It initializes the 8bit machine stack as well as the 16 bit pseudo-stack, loads initialized variables and 
jumps to the main function. 
Also, the interrupt routine shows how to save the important pseudo-registers and pseudo-stack variables before 
calling C functions within an interrupt procedure.

The second, Wdc_Cstartup_816.ASM, is used with the 65c816 compiled program. 
This startup routine switches the CPU to native mode, initializes the 16 bit stack pointer and jumps to the main program. 
It also shows how the interrupt routine saves the important registers before calling a C function from within an interrupt procedure.

Building

There are two batch files (MK02.bat and MK134.bat) for compiling, assembling and linking the 65C02 program. 
There are 8 batch files for compiling, assembling and linking the 65C816 program. 
(MK_Exmpl1_816_x.bat and MK_Exmpl1_265_x.bat, where x is either L, M, C, or S indicating the memory model.) 

For the 65C02 build programs:
	The first statement:
		WDC02AS -g -l -DUSING_xx WDC_Cstartup_02.asm
	assembles the appropriate startup file into the file WDC_Cstartup_02.OBJ. 
		The '-g' option tells the assembler to include source level debugging information in the object module. 
		The -l option generates a listing file. The -DUSING is a directive telling the assembler what chip to use.
	The second statement:
		WDC02CC -bs -lt -DUSING_xx exmpl1.c
	compiles and assembles the EXMPL1.C program into the file EXMPL1.OBJ. 
		The '-bs' option tells the compiler to include source level debugging information in the object module. 
		The -lt option generates a listing with embedded source statements. The -DUSING is a directive telling the compiler what chip to use.
	The third statement:
		WDCLN -c1000 -sz -hz -g -t -o exmpl1.bin WDC_Cstartup_02.obj exmpl1.obj -lxx
	links the startup file with the file EXMPL1.OBJ and the appropriate library. 
		The '-hz' option tells the linker to create the output file as a proprietary binary format. 
		Other options could be used to generate any of a number of standard output formats.
		The '-g' option tells the linker to include source level debugging information in the output. 
		The '-sz' option tells the linker to create a file called EXMPL1.SYM in a proprietary format which can be used by the WDCDB.EXE simulator/debugger.
		The '-t' option creates a file called, EXMPL1.MAP, which is a text listing of all symbols and their addresses.
		The ‘-o’ option tells the linker to call his output file EXMPL1.BIN
		Finally, the '-c1000' tells the linker to set the starting CODE section address to 0x1000.
	The fourth statement:
		WDCSYM -A -L exmpl1.sym>symbols_xx.txt
	executes the utility to examine the symbol files generated by the linker, and places the results in the file symbols_xx.txt. 
	The -A option displays auxiliary tables. The -L option displays line tables.
	The fifth statement:
		WDCOBJ exmpl1>objects_xx.txt
	executes the utility to examine the object files created by the assembler. The results are placed in a file called objects_xx.txt.

For the 65C816 build programs:
	The first statement:
		WDC816AS -g -l -DUSING_xxx -DSMALL WDC_Cstartup_816
	assembles the appropriate startup file into the file WDC_Cstartup_816.OBJ. 
	The '-g' option tells the assembler to include source level debugging information in the object module. 
	The -l option generates a listing file. The -DUSING is a directive telling the assembler what chip to use, and which memory model to use.
	The second statement:
		WDC816CC -lt -ms -bs -DUSING_xxx exmpl1.c
	compiles and assembles the EXMPL1.C program into the file EXMPL1.OBJ. 
		The '-bs' option tells the compiler to include source level debugging information in the object module. 
		The -lt option generates a listing with embedded source statements. 
		The -m(x) option generates code for the appropriate memory model. 
		The -DUSING is a directive telling the compiler what chip to use.
	The third statement:
		WDCLN -c1000 -sz -hz -g -t -o exmpl1.bin WDC_Cstartup_816.obj exmpl1.obj -lxx
	links the startup file with the file EXMPL1.OBJ and the appropriate library. 
	The '-hz' option tells the linker to create the output file as a proprietary binary format. 
		Other options could be used to generate any of a number of standard output formats.
	The '-g' option tells the linker to include source level debugging information in the output. 
	The '-sz' option tells the linker to create a file called EXMPL1.SYM in a proprietary format which can be used by the WDCDB.EXE simulator/debugger.
	The '-t' option creates a file called, EXMPL1.MAP, which is a text listing of all symbols and their addresses.
	The ‘-o’ option tells the linker to call his output file EXMPL1.BIN
	Finally, the '-c1000' tells the linker to set the starting CODE section address to 0x1000.
	The fourth statement:
		WDCSYM exmpl1 > symbols_xxxx.txt
	executes the utility to examine the symbol files generated by the linker, and places the results in the file symbols_xxxx.txt. 
	The fifth statement:
		WDCOBJ exmpl1 > objects_xxxx.txt
	executes the utility to examine the object files created by the assembler. The results are placed in a file called objects_xxxx.txt.
	
Simulating/Debugging
To run the simulator/debugger, simply run WDCDB. 
The WDCDB.INI file has already been set up to run the EXMPL1.BIN program in 65C02 simulation with W65C22S emulation as well. 
A W65C22S.DLL is located in the Wdc_sds\Bin directory. 

To run in emulation mode under the 65C816 simulator, in the file WDCDB.INI, the line 'Target=6502' must be changed to 'Target=65816' first. 
Using the simulator/debugger, the program can be run, single stepped, and memory examined among other functions. 
An on-line help file is available for more information.

******************
WARNING/Caveat:
******************
When writing your own programs, the W65C134 and W65C265 may start up in the slow clock mode at 1st power up!  
Single stepping in the WDCDB may/will be slow until you enable the FCLK.
